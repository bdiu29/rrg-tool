# Market Intelligence Harness — CLAUDE.md

## Project Vision

Personal market intelligence platform to guide investment/trading decisions: avoid drawdowns, catch rotation setups, and surface actionable signals. Built module by module from free data sources, culminating in AI subagents per data domain that feed a unified harness.

**Current state:** Home hub (live status badges) + RRG tool (sector rotation, with a signal/display split and a walk-forward-validated rotation-call backtester) + Schwab account module (positions with sector signals) + Breadth module (market breadth tracker with regime filter) + Screener module (TradingView-style filters, watchlists, intraday pump/dump alerts with Discord/email routing, EMA/golden-pocket filters, and a strategy backtester sidecar) + Rankings module (sector ETF relative-strength leaderboard with 0-99 percentile ranks, rank-up/down movers, and top-stocks-per-sector) + Themes module (user-editable theme baskets → equal-weight indices ranked 0-99 vs SPY with a theme RRG rotation chart, movers, and constituent drill-down) + a shared **Confluence factor layer** (`modules/confluence/` — pure leaves: bull/bear flags, volume exhaustion, **volume profile** POC/value-area/shape, and **accumulation/distribution** U-D-volume/A-D-line institutional footprint, each emitting a signed contribution every module can fold into a decision) + **Options Flow module** (unusual options activity / whale entries-exits: a flow trader's 6-rule filter over Schwab option-chain snapshots, pluggable to a future Polygon trade tape) + **CANSLIM module** (O'Neil/IBD's 7-factor growth scorecard — pure composition of breadth regime, rankings RS, accumulation, and screener fundamentals into a 0-99 per-stock leaderboard) + **News & Macro Events module** (`modules/news/` — a **week-by-week** economic calendar (FOMC + econ releases, FRED Actual/Previous when keyed) + an **earnings calendar** (Finnhub broad/EPS, else focus list) + a **news feed** (market RSS + SEC 8-K + AlphaVantage sentiment) + a **Rates & Curve** tab (Treasury yields, fed funds, curve inversion from FRED), all from free sources, with an **event-risk hook** other pages overlay) + an **AI Subagent Harness** (`modules/harness/` — the synthesis layer and project end-goal: every data module casts a signed VOTE, a **deterministic, regime-arbitrated combiner** (a cross-agent `signal._conviction`) decides a CONCENTRATE-vs-ROTATE stance + composite score + confluence longs/avoids, and Claude **narrates** one daily brief on the user's *subscription* via the local `claude` CLI — **math decides, LLM explains**; runs at $0/offline from the combiner alone). Every page except RRG uses a white/navy palette; RRG keeps the original dark theme.

**Planned modules:** sector/industry trackers (software, space, semis), JPM collar tracking, social sentiment (Reddit/StockTwits, deferred — X is no longer free/reliable). (**AI subagents — done** as the Harness module below.) (News fed-funds-rate *probabilities* deliberately deferred — context not alpha; the Rates & Curve tab covers the macro regime read.)

### Module contract

Each module exposes one function:

```python
def register_routes(router):
    router.get("/path", handler_fn)
    router.post("/path", handler_fn)
```

Route handlers receive a `Request` object and return a `Response`:

```python
from modules import Response

def handler(req):
    # req.path, req.qs (dict), req.headers, req.json_body()
    return Response.json({"key": "value"})
    # or Response.html(html_str)
    # or Response.error("message", status=500)
```

### Adding a new module

1. Create `modules/<name>/__init__.py` with your logic and a `register_routes(router)` function.
2. Drop the frontend HTML at `modules/<name>/<name>.html`.
3. In `app.py`, add two lines:
   ```python
   from modules.<name> import register_routes as register_<name>
   register_<name>(router)
   ```

## RRG Math — Key Parameters

Math lives in `modules/rrg/signal.py`; `__init__.py` is thin (shapes the chart JSON, wires routes). `DEFAULT_TICKERS`/`SECTOR_NAMES`/`BENCHMARK` live in `signal.py` and are re-exported by `__init__` (schwab imports them from the package).

- `DEFAULT_TICKERS` — 11 SPDR Select Sector ETFs (XLK, XLE, … XLC); `BENCHMARK = "SPY"` (all RS relative to this).
- **JdK-style chain (both intervals):** `RS-Ratio` is the fast/slow EMA ratio of RS (a trend measure — x travels with the trend), `RS-Momentum = ROC of that trend` (y is the velocity of x). Momentum being the derivative of the plotted ratio is what makes tails arc clockwise — don't normalize the two axes independently.
- **Signal-space vs display-space — the core decoupling (don't re-entangle these).** Two coordinate systems share the boundary at 100:
  - **Signal coords** (`sig_ratio`/`sig_mom`) drive the chart geometry — quadrant, the EW *display* squash, and the `_accum`/`_distrib` ranking scores. **The rotation call itself no longer comes from these coords** — it is driven by the Elliott-wave/Fibonacci engine on the raw RS line (below). Both intervals are σ-normalized by `_scale(series, window, center)`, which divides by a rolling std about a **fixed center** (RS-Ratio=100 where fast EMA==slow EMA; momentum=0) — **not** a rolling-mean z-score. Fixed-center keeps the boundary honest and interval-independent. The old weekly rolling-mean z-score silently meant "above its own recent average," not "fast EMA above slow" — that bug is gone.
  - **Display coords** (`disp_ratio`/`disp_mom`, the `ratio`/`momentum` arrays sent to the frontend) are a pure cosmetic gain (`DISP_GAIN_X`/`DISP_GAIN_Y`) on the signal coords with the offset **pinned to exactly 100**, so the chart's drawn cross and the frontend's quadrant/crossing logic stay in lockstep with the calls. Changing the gains moves dots and nothing else. This replaced a daily affine map + weekly z-stretch fitted by `calibrate_rrg.py` to a reference image (`sp-rrg.png`) — both deleted; the old `RATIO_C_D=100.55` offset had even shifted the quadrant boundary off the true RS=100 line.
- **Elliott-wave + Fibonacci engine (`_zigzag_swings`/`_classify_wave`/`_wave_features`/`_conviction`/`_rotation_call`).** Real wave structure measured on the **raw RS line** `rs_s = EMA(ETF/SPY, RS_SMOOTH)` — the price-like form where Fib distances mean something (the JdK RS-Ratio oscillation is display-only; do NOT run Fib on it). Swings come from a **volatility-scaled ZigZag** (`_zigzag_swings`): a new pivot registers only when the RS line reverses from its running extreme by ≥ `ZIGZAG_K × rolling σ` — "significant" adapts to each timeframe's volatility (no fixed bar-count to tune; replaced the old ±PIVOT_WIDTH fractal that read 0.03-RS daily noise as swings). The pivot is dated at the extreme but confirmed at the reversal bar → no-lookahead, inherently alternating. It feeds: (a) **retracement depth** classifies a pullback as wave-2 (golden pocket 0.618–0.786 → ROTATE IN) vs wave-4 (shallow 0.236–0.382 → continuation IN); (b) the preceding correction's depth labels the current impulse **wave-3** (after deep w2) vs **wave-5** (after shallow w4); (c) **Fibonacci extension targets** project wave-3 (warn near 2.618×/4.236× w1) and wave-5 (1×w1, 0.618×w1, 0.618×net13, 1.618×net13). **Swings are measured on the WEEKLY cadence** (both views): the daily chart is collapsed to one point per ISO week FIRST, then `_wave_features` runs on `rs.reindex(weekly_dates)` — a ±`PIVOT_WIDTH` fractal of 4-day *daily* bars is noise (a 0.03-RS "swing" produced a 480% retrace live), so golden-pocket levels must come from meaningful weekly swings. `PIVOT_WIDTH`/`PIVOT_SMOOTH` are therefore in **weeks**. `evaluate_tail` reads the head row; `retrace_pct` is exported only for a real corrective wave (wave-2/4), never the nonsensical retrace of a non-setup. **No-lookahead is enforced by a forward-only ZigZag fold** (`_fractal_pivots` raw + `_fold_pivot` applied to the confirmed prefix bar-by-bar) — NOT by slicing a globally-collapsed list, which let a future same-kind pivot retroactively replace a confirmed one (a real leak that inflated the backtest until fixed). Each sector exports `wave_label`/`retrace_pct`/`ext_ratio`/`fib_target`/`trend`/`leg_kind` for the tooltip. The old `t_soft`/`m_adj` tanh squash (`TREND_ETA`/`MOM_TAU`) is now **display cosmetics only** — it shapes the chart dots, not the call.
- **Phase 2 — ABC corrective engine (`_abc_state`, done).** After a five-wave advance tops, the correction is a three-wave A-B-C. The dominant peak triggers ABC **only if its leg was a genuine wave-5** (the full alternation: deep wave-2 then shallow wave-4 — same test that splits w3 from w5, so a wave-3 peak instead reads as a wave-4 continuation dip, Phase-1 territory). Classifies zigzag vs flat by B's retrace of A, projects the C-target zone, and uses the prior wave-4 low as the C-bottom confluence. Calls: wave A → ROTATE OUT, zigzag wave B → ROTATE OUT (sell the bounce), wave C into the target/w4 zone → WATCH/ROTATE IN (a bullish divergence confirms it, Phase 3). Exports `abc_type`/`c_target_lo`/`c_target_hi`.
- **Phase 3 — RSI divergence confirmation + multi-timeframe confluence (done).** Wilder RSI is ported locally (`_rsi` — RRG must not import the screener) and computed on BOTH the RS line and absolute price. `_divergence` reads the same ZigZag pivots: a *forming* read (the live bar pushing past the last confirmed pivot while RSI lags — the project-ahead early signal) backed by a *confirmed* read off the last two pivots. **This gates the entries**: a wave-2 golden pocket / wave-C bottom only fires ROTATE IN with a **bullish** divergence (else WATCH — "waiting for momentum to turn"), and a wave-5 fires ⚠️ w5 extended early on a **bearish** divergence. Multi-timeframe confluence (`_attach_mtf`, best-effort, real-fetch path only): since the structure is weekly, the higher TF is **monthly** (shifted one bar before being forward-filled onto the active dates — no in-progress-bar leak) and the lower TF is **1h** for the daily view (best-effort — limited yfinance history, degrades to "none") / daily for the weekly view. Exports `div_rs`/`div_px`/`div_confluence`; the call reason appends `· confluence: RS+price+HTF`. **This is what made the signal work**: adding divergence lifted the walk-forward mean OOS separation from ~0.19 to ~0.89 (positive in 3 of 4 folds), ROTATE IN +5d excess to ≈+0.56%, ROTATE OUT / ⚠️ w5 clearly negative, win rate ~67% / profit factor ~4. Still a small sample (11 ETFs × 3y) — direction, not precision.
- **Lenses (`LENS` dict — interval-specific time-scale, NOT cosmetic).** Weekly: fast 10w / slow 40w, `mom_diff=5`, σ-windows 52w/26w, `trend_len=12w`. Daily (default): fast 50 / slow 140 trading days, `mom_diff=15`, σ-windows 140d/60d, `trend_len=60d`; `mom_smooth=3` both. Daily is a **macro lens in trading days**, NOT a faster story — short windows read 3-week laggard bounces as rotation. `mom_smooth` is deliberately LIGHT so momentum **leads** the ratio (heavy smoothing = lag = straight tails, no rollover). Daily emits one tail point per ISO week, anchored to each week's **last** bar (not counted back from the newest bar) so points stay put as dates advance.
- **PROBABILISTIC CONFLUENCE MODEL (current — replaced the AND-gate engine).** Elliott wave is probabilistic, so the call is no longer a chain of mandatory gates (clean count AND golden pocket AND divergence — that fired ~7×/3y and couldn't be validated). Instead `_conviction(ws, params)` sums **weighted factors** into a signed score (bullish + / bearish −, clamped to `[CONV_LO=−70, CONV_HI=+99]`): golden-pocket **depth quality** `gp_q` (`_gp_quality`, peaks in 0.618–0.786, valid for wave-2 up to ~99% via `WAVE2_MAX`; ≥1.0 invalidates), impulse **extension quality** `ext_q`, each RSI divergence (RS/price/HTF/LTF), prior-wave-4 overlap, clean-count bonus. No single factor is required; several aligning = high conviction. **Multi-timeframe blend (`_attach_mtf` → `mtf_1mo`/`mtf_1d`/`mtf_1h` columns):** the golden-pocket/wave signal is read on 1h + daily + weekly (active) + monthly via `_wave_features` per TF, reindexed onto the active points (conservative shift, no-lookahead), and summed in `_conviction` weighted by `TF_WEIGHT` (monthly>weekly>daily>1h) — daily+weekly alignment (the common case) stacks. **Bull/bear flag — EMPIRICAL + REGIME-AWARE (`_flag_signal` on the RS line; weight from the real edge, not a flat `W_FLAG`).** Contribution = `W_FLAG_EDGE(150) × max(0, win_rate−0.5) × _flag_regime_factor × ±1`, using the symbol's own win rate when it has ≥ `FLAG_MIN_N(8)` events else `FLAG_BASE_WIN` (bull 0.58, bear 0.50). `_flag_regime_factor` zeroes a flag opposing the current regime (`FLAG_OPPOSING=0`: bear in HEALTHY / bull in DETERIORATING). Detection core is the pure leaf **`modules/confluence/flags.py`** (`_detect`/`_summary`/`win_rates`/`flag_panels`); ETF win rates via `signal.flag_win_rates_for` (in-memory cached). **Volume buyer/seller exhaustion (`modules/confluence/exhaustion.py`, `W_VOL_EXH=14`):** a volume climax into a new high/low that closes weak/strong = topping/bottoming confluence on the symbol's **absolute price+volume** (selling climax +bullish, buying climax −bearish). **Volume profile (`modules/confluence/volume_profile.py`, `W_VOL_PROFILE=12`):** the symbol's price vs its trailing 60-bar volume-at-price value area — in discount (below VAL) = a bullish value-buy, premium bearish, reinforced by a bottoming (b) / topping (P) profile shape; a graded signed strength in [−1,1] × the weight × TF weight, wired in exactly like exhaustion via `signal.volume_profile_for` + the `evaluate_tail(vol_profile=)` kwarg. The regime + per-symbol win rate + exhaustion + volume profile are fetched once per `compute_rrg` (real sectors only; theme synthetic indices → basket default, no volume reads) and are a **live-only refinement** — `backtest.py`/`replay_calls` keep the basket-default flag weight (no point-in-time-regime lookahead); volume profile is trailing/no-lookahead so it could later be promoted into the backtest. `_rotation_call` routes the score through thresholds (`T_IN`/`T_WATCH`/`T_WARN`) into the same 7-value call set; exported as `conviction` (+ `conviction_factors` breakdown). **Searchable params (`signal.DEFAULTS`):** `ZIGZAG_K` (swing detection — changes `compute_series`, cached by it) + `T_IN`/`T_WARN` (call-time). Weights (`W_GP/W_DIV/W_FLAG_EDGE/W_VOL_EXH/W_VOL_PROFILE/W_ACCUM/W_W4ZONE/W_CLEAN`, `TF_WEIGHT`) and Fib ratios are **fixed by judgment/theory, never searched**. Current bake `ZIGZAG_K=1.25, T_IN=40, T_WARN=40` (walk-forward, mean OOS sep ≈1.7 — multi-TF + flag lifted it from ~0.9). **Honest caveat:** the confidence-bucket monotonicity (higher conviction → higher forward excess) is the model's real test and is still NOT clean on the 11-ETF/3y sample (2–13 onsets/bucket = noise); the IN−OUT separation is strong but per-bucket ranking isn't proven. **`modules/rrg/flag_backtest.py`** is a standalone PRICE+VOLUME flag success-rate study (`python3 -m modules.rrg.flag_backtest [--regime]`): bull flags ≈61% continuation, bear flags ≈27% (fail upward in a bull regime). `--regime` conditions on the breadth regime (bull outside / bear inside DETERIORATING) via `breadth.regime.regime_series` + `align_labels` (which fixes the breadth string-date vs yfinance Timestamp index mismatch); on the 3y window bull conditioned ≈62% (n=69) but the bear sample is only n=5 — **no measured bear-flag edge yet** (no real bear market in-sample).
- **As-of rollback:** `compute_rrg(..., asof="YYYY-MM-DD")` / `GET /api/rrg?asof=` truncates history to show the RRG as of a past date. All windows are trailing, so rollback only removes head points. Price downloads cached 10 min in `signal._PRICE_CACHE` (close) / `_OHLC_CACHE` (backtest OHLC). Weekly bars are Monday-dated and hold the full week, so weekly rollback has whole-week granularity.
- **"vs SPY" bars panel — lookback slider + Level/Δ toggle (frontend display).** The diverging bar chart under the RRG ships a `rel_hist` array per sector — the relative move vs SPY (an **excess return**: `rel_hist[k]` = sector_ret − SPY_ret over `k+1` trailing **bars of the active interval**) for 1..`max_lookback` bars (`LOOKBACK_BARS`: 30 days / 12 weeks), computed no-lookahead by `_rel_hist` from the same close panel. A **lookback slider** picks the window and a **`Level | Δ` mode toggle** picks what the bar measures, both re-rendering with **no refetch** (the whole series is in the payload): *Level* = the cumulative excess move over the window (`rel_hist[lb−1]`; lb=1 = the original "Today/This Week vs SPY"); *Δ* = **acceleration** — `relAccel` splits the window into two equal halves and subtracts the prior half's excess from the recent half's (`recent − (rel_hist[2h−1] − rel_hist[h−1])`, the additive first-difference approximation), so + = outperformance speeding up, − = rolling over ("momentum turns first"). Δ needs ≥2 bars (entering Δ from a tiny window auto-bumps the lookback). Bars are **shaded by magnitude** (opacity floored at 0.4 × `|val|/maxAbs`) so size *and* shade read how far/fast each sector moved. Purely additive to the `compute_rrg`/`/api/rrg` output (`rel_hist`, `max_lookback`, `lookback_unit`) — the Δ math is all client-side; the golden-master fixture was regenerated for the added fields (no existing value changed).

Tunable scoring/decision functions in `modules/rrg/signal.py` (fed σ-scaled signal coords):
- `_accum()` / `_distrib()` — rotate-in / rotate-out **ranking** scores (σ-tuned coefficients; used for the "best" pick and the IN/OUT bucket ordering, *not* the binary call).
- `_rotation_call(ws, params)` — wave/Fib state → `(call, why)`. **`call` is one of seven values** (`backtest.CALL_ORDER`): the five rotation states {ROTATE IN, ROTATE OUT, HOLD, AVOID, WATCH} plus the two extension warnings **`"⚠️ w3 extended"` / `"⚠️ w5 extended"` as first-class calls** (`signal.WARN_CALLS`) — so the event study scores them on their own forward returns (the larger 40-ETF study reversed an earlier read: ⚠️ w5 extended is ≈ +1.3% excess at +10d — continuation, not exhaustion — which is why it's no longer a backtest exit; see below). Uptrend: wave-2 GP → IN, wave-4 shallow → IN, wave-3 → HOLD or ⚠️ w3 extended near 2.618×, wave-5 at target → ⚠️ w5 extended; downtrend mirrors (GP bounce → OUT, extended down-impulse stays AVOID/WATCH — a bottoming setup, NOT a warn call); no clean structure → WATCH. Backtest: `EXIT_CALLS = (ROTATE OUT, AVOID)`; **both** extension warnings are now "hold but tighten", NOT exits — the event study showed ⚠️ w5 extended has strongly POSITIVE forward excess (+1.3% at +10d, i.e. continuation, not exhaustion), so exiting a long on it was selling winners early (removing it from the exits lifted the 40-ETF equity +98→+103% at equal drawdown). It also no longer counts on `_separation`'s bearish OUT side. **Downstream:** schwab still maps `call ∈ WARN_CALLS` → amber **TRIM** (a cautionary late-cycle *risk* flag, deliberately kept even though mean forward return is positive); rrg/screener/themes badge them via `CALL_STYLE`/`rrgBadge` (+ a static call legend on themes).

### RRG backtester (`modules/rrg/backtest.py`)

Validates the *call*, not a chart's appearance. Replays `signal.replay_calls` over history and asks: when the tool says ROTATE IN, does the sector beat SPY next?

- **Event study (the headline, model-independent):** forward returns and excess vs SPY at +1/5/10/20d grouped by call type, measured from the first bar **after** the signal confirms — no lookahead (daily = next bar; weekly = the bar after that week's Friday, since Monday-dated weekly bars aren't known until week-end). A working tool shows ROTATE IN positive excess, ROTATE OUT negative.
- **Trade sim + equity curve:** long on a ROTATE IN onset at the next bar's open; exit on the opposing call (`signal`), a fixed `hold` N bars, or an `atr` stop/target. Equal-weight daily mark-to-market. Because the signal is long-only and selective, the equity report carries **time-in-market** and **two SPY benchmarks**: `SPY (always in)` (fully invested) and `SPY (matched)` (SPY earning only on the days the strategy is invested) — the matched curve is the apples-to-apples read (isolates sector selection from cash drag; don't compare a part-time long-only signal's total return to an always-invested benchmark). Mirrors the screener backtester's conventions but is **RRG-local** (no screener import — RRG sits below screener in the dependency order).
- **Contribution by symbol (`_symbol_contributions`):** per-symbol Σ-return / avg / win-rate / best-worst + a **concentration read** (top-3 / top-5 share of the gross summed return). The honest check on whether a flattering equity curve is broad or carried by a few names: on the 40-ETF set the +103% was top-3 ≈ 51% (KRE+KBE — two correlated *bank* ETFs — plus a few 1–3-trade winners), i.e. one macro theme + small-sample luck, not broad rotation skill. Σ-return is a simple sum of trade returns, a first-order read (not an exact equal-weight P&L split).
- **Cross-sectional rotation portfolio (`_rotation_portfolio` + `_state_panels`/`_leg_weights`, `config.portfolio`):** the long/short **top-N** sim that monetizes the *ranking* edge the per-trade long-only sim above structurally can't express (it buys *every* sector that flashes IN). `replay_calls` already emits a **dense** per-date `{call, conviction}` for every ticker → `_state_panels` reshapes that into `[date × ticker]` call/conviction DataFrames; `_leg_weights` picks the **top `n_long` ROTATE INs by conviction** (long, +) and the **`n_short` most-negative ROTATE OUTs** (short, −), equal-weight within each leg, rebalanced as ranks/calls change. The rotation-off gate (reusing `_rotation_series`) **flattens the book** in a concentration regime. **No-lookahead:** weights decided at a bar's close earn that bar→next close-to-close (`shift(1)`) — 1 bar tighter than the open-entry trade sim, noted in the caveats. **Two short constructions, because the signal is a RELATIVE edge (excess vs SPY):** (a) `long_short`'s **market-neutral spread (long − short sectors)** is the pure ranking edge but it *shorts absolute price*, so in a bull tape it eats full market beta on the short leg (a ROTATE OUT sector lags SPY yet still rises — the live 34-ETF run had the short basket at −27.7% dragging the spread to −12.9%); (b) **`long_hedged` shorts the BENCHMARK** (`long − SPY`, the hedge notional = the long book's gross exposure 0/1) — the beta-removed bet that matches the excess-vs-SPY the call actually claims, so it pays when a long merely *outperforms* instead of needing the short sectors to *fall*. Returns equity curves for the chosen `mode` ∈ `long_short`/`long_only`/`short_only`/`long_hedged` **plus the long-only leg, the spread, AND the hedged curve always computed for side-by-side comparison** + a **leg-return decomposition** (long / short-basket / hedge — is the edge in the longs, the short sectors, or the relative-to-SPY bet?) + avg #long/#short, turnover, exposure, DD/Sharpe, vs SPY-matched. Trading costs not modelled (turnover is reported so churn is visible). Unit-tested in `tests/test_rrg_rotation.py` (exact top-N-by-conviction selection, hand-checked leg P&L, the `shift(1)` no-lookahead, gate-flattens-when-off, and `long_hedged` subtracting the benchmark — drag below long-only when SPY is up, equal when SPY is flat).
- **Take-profit ladder comparison (`_tp_comparison` + `_tp_schedule`/`_simulate_scaled`/`_scaled_equity_curve`, `report.tp_comparison`):** instead of a binary exit-on-ROTATE-OUT, scale out 20/40/60/80/100% over five rungs — and compare **four ways to TRIGGER the rungs head-to-head over the SAME entries** (only the exit mechanic changes — a controlled test; entries are the ROTATE IN onsets, each trade's terminal capped at the next entry so variants stay non-overlapping and identical): `full` (baseline binary exit on the first ROTATE OUT/AVOID), `calls` (each escalating late-cycle call caps remaining size: ⚠️ w3 ext→80% · ⚠️ w5 ext→60% · ROTATE OUT→40% · AVOID→20% · terminal→0, a skipped rung still trims down to that ceiling), `post_out` (hold full through the warnings — keeping the w5 continuation — then sell 20%/bar for 5 bars once an exit call fires), and `fib` (sell 20% as the bar's high tags each Fibonacci extension `0.618/1.0/1.618/2.0/2.618×` of the entry leg = entry − trailing-`FIB_LOOKBACK`(20)-bar low; fills at the target price). Each variant's trade is a **blended fraction-weighted return** + a step schedule fed to **`_scaled_equity_curve`** — a fraction-aware equal-weight daily mark (a position contributes its REMAINING fraction; full size reproduces the boolean `held` curve). The comparison tabulates return / maxDD / Sharpe / win / PF / time-in-market per exit + an equity overlay + a `best` pick per metric. **Honest framing (surfaced in the note):** late-cycle calls are CONTINUATION (⚠️ w5 ext ≈ +1.9% at +10d), so trimming into them trades total return for lower drawdown — this is **exit-side risk management, not entry edge** (it can't manufacture the forward excess ROTATE IN lacks); `fib` rungs fill at the target while the equity marks close-to-close (a small intrabar nuance). Computed always in `run_backtest` (cheap — reuses the loaded calls/frames); unit-tested in `tests/test_rrg_tp_ladder.py` (each trigger's exact rung fractions/bars in bar-space + a blended-return/equity integration check).
- **`walk_forward_search`:** expanding-window folds; per fold picks the in-sample-best gate combo and scores it out-of-sample; recommends the combo with the best **mean OOS** separation (robust, not the global optimum) and reports IS vs OOS per fold so overfit is visible. Small grid on purpose — with only 11 ETFs × ~3y this is a **guardrail, not a fitting machine**; the caveat is surfaced in the report.
- **Toggleable universe (`backtest.UNIVERSES`):** `sectors` (default, 11 SPDR ETFs) or `etfs` (~40 liquid sector+industry ETFs — semis/biotech/software/miners/banks/etc., all ≥3y). The broader set fights the tiny-sample noise in the confidence buckets — ~4× the ROTATE IN onsets (≈24 → ≈100). Self-contained ETF list (no fundamentals / cross-module dep, since RRG sits at the bottom of the dependency order).
- **Toggleable benchmark (`backtest.BENCHMARKS`):** the excess + equity are scored vs `SPY` (cap-weight, default) or `RSP` (equal-weight). The **signal is always RS-vs-SPY** (the calls never change) — only the yardstick swaps. RSP is the fair bar for sector rotation: it strips the mega-cap-beta penalty that makes SPY near-unbeatable in a concentration regime.
- **Rotation-regime split (`_rotation_series` / `_regime_split_study`):** every ROTATE IN/OUT onset is tagged with the rotation regime at that date — `on` when RSP/SPY is above its 50d EMA (breadth broadening), `off` when below (concentration). The event study splits IN/OUT excess by on/off. The finding that motivated the gate: on the ~40-ETF set, **ungated** ROTATE IN excess was clearly positive when rotation is on (≈+0.7%/+0.5% vs SPY, ≈+1.5%/+1.7% vs RSP at +10/+20d) and strongly negative when off — the signal isn't broken, it's regime-dependent (2023–24 was largely a concentration regime). Regime computed inside rrg from RSP (no breadth dep), fail-soft.
- **ROTATION-REGIME GATE — now in the live engine AND the backtest (no-lookahead).** `signal._conviction` subtracts `W_ROTATION_OFF`(30) from conviction when rotation is off (`signal.rotation_regime()` live; a per-date `_rotation_label` Series fed through `replay_calls(..., rotation=)` in the backtest, asof-looked-up so it's no-lookahead). No on-boost (`W_ROTATION_ON=0` — boosting only drags marginal entries over `T_IN` and dilutes the good bucket). Because the regime is trailing/no-lookahead, it gates the backtest too (unlike the live-only flag/exhaustion refinements), so the backtest validates it: on the 40-ETF/3y set the gate lifts strategy equity **+67%→+88%**, cuts max drawdown **−21%→−14%**, drops to **55 (from 70) more-selective trades**, and now beats SPY-matched (it trailed before). Exposed in `evaluate_tail`/`compute_rrg` output + the `/api/rrg` payload as `rotation`. **Caveat:** after gating, the per-regime event-study buckets are survivorship-distorted (the gate keeps only high-conviction off-entries) — read the equity/drawdown improvement, not the post-gate buckets.
- Route: `POST /api/rrg/backtest {timeframe, tail, exit:{model,...}, universe, benchmark, walk_forward, portfolio:{mode,n_long,n_short,gate}}` → JSON report (`config.universe`/`benchmark`/`portfolio`/`n_tickers` + `regime_study` + `rotation_portfolio` echoed). Frontend: a "Strategy Backtest" tab on `rrg.html` with **universe + benchmark dropdowns + a rotation-portfolio control group** (mode dropdown incl. `long_hedged` "Long − SPY" · #long/#short inputs · gate toggle) — Plotly equity curve + histogram, per-call-type table, rotation-regime split table, conviction-bucket table, **rotation-portfolio leg-decomposition stats + its own equity chart (strategy / Long − SPY hedged / L−S spread / long-only / SPY-matched)**, walk-forward fold table, Markdown export. Runs synchronously (sector daily ≈ 4s; the ~40-ETF set is proportionally slower).

## Breadth Module

Market breadth tracker: short-term timing signals (McClellan, TRIN, % above 20/50d) read **through** a long-term regime (Summation, % above 200d, divergence flags). Breadth is always plotted against index price on a shared time axis.

**Data flow:** `DataSource` adapter → SQLite store → `breadth_daily` aggregates → derived chains → regime/divergences computed at request time.

- **Adapters** (`datasource.py`): `SchwabDataSource` default — market data base `https://api.schwabapi.com/marketdata/v1`, token via `modules.schwab.get_access_token()` (the only breadth→schwab import), paced at 110 req/min under the 120 hard limit, retry/backoff on 429/5xx, symbol translation `BRK.B`→`BRK/B`. `YFinanceDataSource` is the automatic fallback (and supports bulk chunks of 200; translation `BRK.B`→`BRK-B`). Index symbols per adapter live in `universes.json` (`^NYA`/`$NYA`, `^IXIC`/`$COMPX`); if Schwab rejects an index symbol the sync falls back to yfinance for that series only.
- **Universes** (`universes.json` + `universes.py`): sp500 (Wikipedia scrape via bs4 — **no lxml installed**), nyse/nasdaq (nasdaqtrader.com symbol directories, common stock only — warrants/units/preferreds filtered by name keywords). Config-driven; a generic `csv_url` fetcher exists so Russell 2000/S&P 600 are config entries. **Survivorship**: lists are today's members; membership is stored dated (`members.first_seen/last_seen`) so point-in-time lists can be imported later. The caveat is displayed on the dashboard and in summaries — keep it.
- **Sync** (`backfill.py`): singleton daemon-thread job; 3y backfill (`HISTORY_YEARS`), incremental after that (per-symbol `sync_state.last_date`, 7-day overlap re-fetch, idempotent upserts). Resume = just re-run. S&P 500 ≈ 5 min via Schwab; NYSE/Nasdaq ≈ 20–40 min. **This is why app.py uses ThreadingHTTPServer** — a sync must not block the dashboard.
- **Math** (`indicators.py`, unit-tested in `tests/`):
  - **McClellan is RATIO-ADJUSTED** (`rana = 1000·(adv−dec)/(adv+dec)`, osc = EMA19−EMA39) — deliberate deviation from the classic raw-net-advances form: universes are runtime-swappable (500 vs 3,000 issues) and regime thresholds (`MCC_OVERSOLD=-70` etc.) must be scale-independent.
  - **Summation Index uses the closed form `19·EMA39 − 9·EMA19`, NOT `cumsum(osc)`.** The cumsum identity is `Σosc = 19·E39 − 9·E19 − 10·rana₀` — a plain cumsum carries a permanent `−10·rana₀` artifact from the arbitrary first day of stored history (this was found live: a +600 first-day rana put the summation at −5,937 in a positive-breadth market). The closed form's increment still equals the oscillator exactly; steady-state level ≈ 10× average rana. Don't "simplify" it back to cumsum.
  - % above MA / new highs-lows use per-day **eligible counts** as denominators (a symbol needs 200 bars before it counts for pct_above_200) — keeps young listings from distorting percentages.
  - **Short-term EMA thrust:** count and % of names above their 5/10/20-day EMA (`n_above_{5,10,20}ema` / `pct_above_{5,10,20}ema`), same eligible-denominator discipline as the SMA block — a fast breadth-thrust read that leads the 20/50/200d SMA panel. `breadth_daily` gains these via ALTER-ADD-COLUMN migration in `init_db`; they backfill on the next sync's aggregate **recompute from stored bars** (no re-download). New panel on breadth.html (yaxis `y12`).
  - Bullish Percent Index: stubbed (needs a P&F signal engine).
- **Breadth Tape — Stockbee "Market Monitor"** (`indicators.market_monitor(close, high, low)` + `build_tape` in `__init__.py`; a **tab on `breadth.html`**, not a separate page): a dense daily table (newest day on top) of raw cross-sectional counts — stocks up/down 4% today, the 5/10-day ratio of (Σ up4%)/(Σ down4%), up/down ≥25% over a quarter (65d), up/down ≥25%/≥50% over a month (20d), up/down ≥13% over 34d, a **10× ATR extension** count (close ≥10×ATR(14) above its SMA50), **>50dma** (% above the 50-day SMA), the eligible **Stock Universe** count, and the real **S&P** (^GSPC) close. Same per-day **eligible-denominator** discipline as `daily_aggregates` (a symbol counts toward an N-day window only once it has N prior bars). `market_monitor` is **pure pandas** and **does not touch `daily_aggregates` or the persisted `breadth_daily` table** — it's computed on demand from the bars panel and memoized in `_TAPE_CACHE` keyed on the universe's newest stored date (a sync busts it). Scope toggles `all` (default, NYSE∪Nasdaq — broad enough for hundreds-of-stocks counts; sp500 alone is single-digit) / `sp500` / `nyse` / `nasdaq`. `^GSPC` isn't in the synced universes, so `_ensure_gspc()` lazily fetches it via the yfinance adapter and upserts into `bars` (idempotent, fail-soft → null S&P column on failure). Frontend = a heat-colored HTML table (no Plotly) inside `breadth.html`'s Tape tab: bull counts shade green, bear counts + ATR-ext shade red, ratios green>1/red<1, >50dma green>50/red<50, all relative within each column over the shown rows; plus Advancing/Declining and New-High/New-Low gauge bars and a **Copy as image** button (html2canvas → clipboard PNG, download fallback). The dashboard tab's chart render is fail-loud: if Plotly's CDN doesn't load it shows an honest error instead of a stuck "loading…".
- **Regime** (`regime.py`): scored — Summation sign + 5d slope + %>200d (≥60 broad / <50 narrow) − active divergence flags; `≥3 → HEALTHY` (all legs green required), `≤−2 → DETERIORATING`, else NEUTRAL. **Divergences are discrete dated events**: index makes a fresh 63d high above its prior one while A-D line / %>50d / %>20d sit below their value at that prior high (bullish mirror at lows); flags stay "active" 21 bars. `interpret()` maps short-term extremes through the regime (oversold in HEALTHY = buy-the-dip; same print in DETERIORATING = fade, smaller, tighter). Thresholds are named constants at the top — tune there.
- **Routes:** `GET /breadth.html`, `/api/breadth/universes`, `/api/breadth/dashboard?universe=&days=`, `/api/breadth/summary?universe=`, `/api/breadth/tape?universe=&rows=`, `/api/breadth/progress`, `POST /api/breadth/sync {universe, source?}` (409 if a job is running).
- **Store** (`modules/breadth/data/breadth.db`, gitignored): WAL mode, per-call connections (backfill thread + request threads coexist); symbol IN-queries chunked at 500 (SQLite bound-variable limit).
- Daily summary CLI: `python3 -m modules.breadth.cli [universe] [--json]` — same code path as `/api/breadth/summary`; the homepage badge reads the same endpoint.

## Screener Module

TradingView-style screener over the full synced universes (sp500 ∪ nyse ∪ nasdaq from breadth.db, ~5.3k symbols), with saved screens, watchlists, and pump/dump alerts on a **focus list** = Schwab positions ∪ watchlist symbols.

**Architecture:** scans never compute indicators per-request. A background job (`snapshot.py`, breadth-backfill thread pattern) rebuilds a `snapshot` table (one indicator row per symbol — chg/gap/vol-chg/RVOL, SMA20/50/150/200, EMA5/10/20/50/100/200, RSI14, ATR14, RS vs SPY 1m/3m, shifted 20d/252d high-low levels, golden-pocket fields) from breadth's bars in ~5s whenever bars are newer than the snapshot; scan requests are sub-second pandas filters over it. The scan handler auto-kicks a rebuild when stale and serves the old snapshot meanwhile. **`metrics.compute_indicator_panels` is the single source of truth** — it computes every indicator vectorized over the *full* date×symbol panel; `compute_snapshot` just collapses it to the last row, and `backtest.py` keeps the whole history. The `snapshot` table is fully derived, so the schema migration (`store._migrate_snapshot`) simply drops & recreates it when columns are added — the next refresh repopulates it.

- **Filter engine** (`filters.py`): screens are JSON condition lists `[{field, op, value}]` ANDed; ops `> >= < <= == != between in`. **NaN never matches** (TradingView semantics — no market cap ⇒ fails every market-cap condition). The `FIELDS` registry drives both validation and the frontend dropdown — add a field once. Levels stored with `shift(1)` so "price crosses yesterday's 20d/52w high-low" is detectable; `%-off-52w-high` uses the inclusive extreme (fresh high reads 0). `price_vs_emaN_pct` (5/10/20/50/100/200) and `price_vs_smaN_pct` are derived at scan time in `derive_scan_columns`. Built-in seeded screens "Breakout"/"Continuation" (the user's real TradingView presets), "Golden Pocket"/"Approaching Golden Pocket", "Volume Building" (RVOL ≥ 2, |chg| ≤ 3% — the full-universe scan twin of the vol-building alert), "Bull Flag"/"Bear Flag"/"Selling Climax"/"Buying Climax", and "Under Accumulation" (`ad_rating in [A,B]` — the demand side of CANSLIM's S) — keep them.
- **Flag + exhaustion + accumulation fields** (`metrics.flag_panels` / `exhaustion_panels` / `accumulation.panels`, reused from the confluence `flags`/`exhaustion`/`accumulation` leaves — single source of truth): `flag` (bull/bear/none, the vectorized twin of `flags._detect`, pinned to it by a test), `exhaustion` (buyer/seller/none, a volume climax into a new high/low closing weak/strong), and `ad_rating` (A–E accumulation/distribution = the institutional buy/sell footprint; seeds the "Under Accumulation" screen, `ad_rating in [A,B]`). All str snapshot FIELDS.
- **Per-stock flag win-rates** (`flagstats` background job in `snapshot.py` → `flag_winrate` table): each universe symbol's own historical bull/bear flag win-rate (continuation success), regime-conditioned via `breadth.regime.regime_series`, **incremental + chunked, cached ~90 days per symbol** (`stale_winrate_symbols`; the user wants these recomputed rarely). Kicked lazily (once/day) by rankings/themes via `rankings.flag_stats_for`; read with `store.get_flag_winrates`.
- **Golden pocket** (`metrics.golden_pocket`): the most recent swing leg's Fibonacci retracement. Pivots are *strict* local extremes over ±`GP_PIVOT` bars (strictness ignores flat runs that would read as both a high and a low) and are confirmation-lagged by `GP_PIVOT` (shift forward then ffill) so there's **no lookahead**. The active leg is the more recent of the last swing high/low: recent high ⇒ *bullish* (low→high, retracing down), recent low ⇒ *bearish* (high→low, retracing up). Exposes `gp_direction` (str), `gp_retrace` (0–1), `gp_in_pocket` (1.0 when 0.618–0.786), `gp_approaching` (1.0 when `GP_APPROACH_FLOOR`=0.5 ≤ retrace < 0.618 — lead time before the zone, excludes blown-through > 0.786), and `gp_zone_low/high` (the pocket as price levels).
- **Backtester** (`backtest.py`, `POST /api/screener/backtest`): replays the live scan over history. For each trading date it rebuilds the same cross-section the scanner filters (from `compute_indicator_panels` + fundamentals) and runs the same `apply_filters`; matches are entry signals. **Long-only; entries fire on signal *onset*** (matched today, not yesterday — a persistent signal = one trade) and execute at the **next bar's open** (no lookahead). Exit models (configurable): `hold` N bars, `atr` (stop = entry − k·ATR14, target = entry + k·ATR14, stop checked first), `signal` (exit when the symbol stops matching). Records per trade: prices, return, bars, MFE/MAE, exit reason, forward returns at +1/5/10/20d (close-to-close, with excess vs SPY), and the **full signal feature vector at entry** (the ML-ready payload — no model yet, that's the Phase-2 hook). Aggregates: trade stats (win rate, expectancy, profit factor, payoff), a forward-return study, and an equal-weight daily mark-to-market equity curve vs SPY. Runs synchronously (sp500/3y ≈ 4s); default universe `sp500`. **Caveats it surfaces:** fundamentals/earnings/`rrg_call` use latest-known (not point-in-time) values — `rrg_call` matches nothing historically; universe is today's members (survivorship). The frontend report widget (Plotly equity curve + return histogram) exports to Markdown.
- **Fundamentals** (`quotes.get_schwab_fundamentals` + `snapshot._run_fundamentals`): Schwab `instruments?projection=fundamental` accepts comma-separated batches (100/call verified live; field names `marketCap`, `sharesOutstanding`, `avg10DaysVolume`, `peRatio`, `dividendYield`, `beta` — Schwab reports missing numerics as 0.0, stored as NULL). Full universe ≈ 1 min. yfinance fills the gaps (phase 2), then earnings dates for the focus list only (phase 3 — full-universe calendar fetch is too slow), the sector long tail (phase 4, only source for sector — also grabs **EPS growth** from the same `.info` for free), **EPS-growth refresh** (phase 5, `eps_growth_q`/`eps_growth_a` for CANSLIM C/A, every `GROWTH_MAX_AGE`=30d), and **institutional ownership** (phase 6, `inst_pct_held`/`inst_holders_count` from yfinance into the dated `inst_ownership_history` table for CANSLIM's I, every `INST_MAX_AGE`=80d so a QoQ delta accumulates — gated on the history's own dates, not `updated_at`). All phases resumable via per-symbol `status/updated_at` (inst via the history table). `fundamentals` gains `eps_growth_q/_a`, `inst_pct_held`, `inst_holders_count` via an **ADD-COLUMN migration** (`_migrate_fundamentals`, real data so not drop/recreate like the snapshot).
- **Alerts** (`rules.py` + `poller.py`): dedupe is structural — `UNIQUE(date, symbol, rule_key)` + `INSERT OR IGNORE`, so a rule fires at most once per symbol per day and external channels only ever see newly inserted rows. Heuristics (constants at top of `rules.py`): vol thrust (RVOL ≥ 3 AND |chg| ≥ 3%), vol building (RVOL ≥ 2 while |chg| < 3% — volume leading price, the pre-pump read; mutually exclusive with thrust at any instant, but distinct rule keys let a name escalate building → thrust same day), RSI 80/20, ±15% SMA20 stretch, 20d/52w level breaks (52w suppresses the 20d echo), ±4% gaps, earnings ≤ 7 days. Extremes carry the kind of the *reversal* they warn about (overbought ⇒ dump). Any saved screen can be **armed**: fires only when a focus symbol *newly* matches (`screen_matches` table remembers the previous match set).
- **Intraday poller** (`poller.py`): singleton daemon, auto-started in `register_routes`; ticks every 180s during 9:30–16:00 ET Mon–Fri, idles otherwise (holidays unmodeled — empty polls are harmless). Pulls rich Schwab quotes (running `totalVolume` — the field yfinance can't provide), patches focus-list snapshot rows in memory (live RVOL = volume ÷ session-fraction-prorated 10d avg, floored at 2% of the session to stop open-bell blowups), runs the rules + armed screens. The EOD pass after each snapshot rebuild reuses the same `run_alert_pass` path, so alert logic exists exactly once. **Gotcha fixed once already:** `time.monotonic()` starts near 0 per process on macOS — never use `0.0` as a "never fetched" cache sentinel; use `None`.
- **Notify** (`notify.py`): in-app always; per-watchlist channel routing — alert for symbol S goes to every channel of every watchlist holding S, plus the `positions_channels` meta setting for held symbols. One batched Discord post / email per pass; fail-soft (channel errors recorded in status, never raised into the poller). `.env` keys: `DISCORD_WEBHOOK_URL`; `SMTP_HOST`/`SMTP_PORT` (465 SSL)/`SMTP_USER`/`SMTP_PASS`/`ALERT_EMAIL_TO`.
- **Routes:** exact-path router ⇒ POST-verb CRUD. `GET /screener.html`, `/api/screener/{status,progress,fields,screens,watchlists,alerts,alerts/summary}`, `POST /api/screener/{refresh,scan,backtest,screens/save|delete|arm,watchlists/save|delete,alerts/ack,notify/test,settings,poller}`. `scan` accepts `{conditions|screen_id, universe, symbols?, sort, dir, limit}` — `symbols` powers the watchlist "view" button. `alerts/summary.by_symbol` drives the home badge and the alert dots on schwab.html.
- **Store** (`modules/screener/data/screener.db`, gitignored): WAL, per-call connections, same conventions as breadth. Bars are **read from breadth's store** — never duplicated.
- ATR risk sizing is frontend-only: the "Risk $" input adds a Shares column = floor(risk ÷ ATR14).

## Rankings Module

A scannable companion to the RRG chart: the 11 SPDR sector ETFs scored 0-99 by relative strength vs SPY, served at `/rankings.html`. Math + routes live in `modules/rankings/__init__.py`; the frontend is pure tables/cards (no Plotly).

- **The 0-99 rank is a *pooled historical percentile* of an RS composite — NOT an ordinal 1-of-11 rank.** The composite is a weighted blend of relative-strength (`ETF/SPY`) returns over several horizons (`RS_LOOKBACKS` = 21d/63d/126d, tunable). Build that composite for all 11 sectors across the full 3y panel, pool every value into one reference distribution, and map each sector's current composite to its percentile in it (`_percentile_mapper` via `np.searchsorted`). Pooled-historical (not ordinal-among-11) is deliberate: with only 11 names an ordinal rank is a coarse 100/90/80… ladder with near-meaningless day-over-day deltas; the percentile spreads non-uniformly **and** moves smoothly, which the rank-movers widgets need. Don't "simplify" it to `rank()` across the 11.
- **Historical rank columns (1D/1W/1M)** read the same percentile mapper on the composite at rows 1/5/21 trading days back — one panel computation yields now + all look-backs, no repeated `asof` calls. The frontend stacks a **rank-movement arrow** under each historical pill (`rankDelta`/`histCell` in rankings.html): `rank_now − rank_{1d,1w,1m}` rendered as ▲/▼ + the number of ranks moved (green up / red down / ±0 flat) — purely a display read of the existing columns, no backend change. **Rank-up/down movers** = `rank_now − rank_{1d,5d}`, top 5 each way (`_rank_movers`).
- **Reuses RRG primitives, never duplicates downloads:** `signal._fetch_close(DEFAULT_TICKERS + [SPY], "1d", PERIOD)` (the 10-min-cached path) and the same `rs = close[t]/close[SPY]` construction `compute_series` uses. Display columns (RS day/wk/mth %, % off 52w-high) come straight off the close panel.
- **Top-stocks-per-sector — a frontend toggle between two definitions of "top":**
  - *Relative Strength* (default): `store.fetch_sector_leaders(sector_etf, n)` JOINs `fundamentals.sector_etf`→`snapshot.rs_1m_pct ORDER BY rs DESC` — the strongest names *classified* into that SPDR sector across the synced universe (NOT the ETF's real basket). Shipped in the main `/api/rankings` payload (`leaders`), each row enriched with its **flag win-rate + current volume exhaustion** via `flag_stats_for` (reads the screener `flag_winrate` table + snapshot `exhaustion`; kicks the flagstats precompute if stale). The frontend shows a "▲NN% / climax↑↓" cell (muted below `FLAG_MIN_N`=8 events). **Caveat surfaced in the UI:** sector tags come from the screener's yfinance fundamentals phase (slow, possibly partial) and need a built snapshot; an empty sector renders a "run a screener sync" note (fail-soft — the page never blocks).
  - *Top Holdings*: the ETF's **actual** top holdings by index weight, from yfinance `Ticker(etf).funds_data.top_holdings` (~10 names + weights), enriched with `store.fetch_quotes` price/chg. Fetched **on demand** per sector via `GET /api/rankings/holdings?sector=XLK` (not in the main payload — it's a per-ETF network call), cached `_HOLDINGS_TTL`=6h; transient failures return `[]` and are **not** cached so they retry.
- **Routes:** `GET /rankings.html`, `GET /api/rankings` (sectors + 4 mover lists + RS leaders), `GET /api/rankings/holdings?sector=` (on-demand ETF holdings), `GET /api/rankings/summary` (hub badge: leading sector + rank). Math + holdings transform unit-tested in `tests/test_rankings.py`.
- **Navigation:** reachable from every page — a hub card plus a `Rankings →` link in each page's cross-nav header (rrg/breadth/schwab/screener); the rankings page carries the reciprocal cross-nav.

## Themes Module

A relative-strength tracker for **user-defined investment themes** (Optics & Photonics, Data Centers, Software, Defense, Space, AI Biotech seeded; editable in the UI), served at `/themes.html`. Themes overlap freely (a ticker can be in several) and aren't GICS sectors, so each is a hand-curated ticker basket.

- **The whole module is wiring, not new quant** — a theme is a **synthetic equal-weight index** fed through the *existing* engines. Enabled by a backward-compatible `close=None` parameter threaded through `signal.compute_series`, `rrg.compute_rrg`, and `rankings.compute_rankings`: pass a pre-built close panel and they skip their own `_fetch_close`. Default `None` ⇒ identical prior behavior.
- **Equal-weight index** (`_build_panel`, [themes/__init__.py](modules/themes/__init__.py)): `(1 + close[constituents].pct_change().mean(axis=1).fillna(0)).cumprod()*100`. **Mean-of-returns, not mean-of-prices** (a $900 name must not dominate a $20 one); `skipna` lets a constituent contribute only from its inception, so early index history reflects fewer names. Keyed `T<id>` (synthetic column per theme) + the real `SPY` column → one panel, one cached fetch.
- **What the page shows off that panel:** theme **ranking 0-99 + movers** via `compute_rankings(keys, "SPY", close=panel)`; theme **RRG** (quadrants, tails, ROTATE calls) via `compute_rrg(keys, "SPY", interval, close=panel)` — the daily/weekly toggle builds a weekly panel from weekly closes; **constituent leaders** computed off the same closes (`rs_1m`/`rs_3m` = stock − SPY return), each enriched with its **flag win-rate + volume exhaustion** via `rankings.flag_stats_for` (off-universe tickers get blanks — fail-soft). Synthetic `T<id>` tickers are post-processed back to theme names from the theme map.
- **Store** (`store.py`, `modules/themes/data/themes.db`): DB-backed CRUD mirroring the screener watchlist pattern — `themes` + `theme_symbols`, `save_theme`/`list_themes`/`delete_theme`/`seed_builtin_themes`, `BUILTIN_THEMES` seeded on first init (idempotent). Editing a theme then reloading recomputes everything (the price cache keys on the symbol set).
- **Frontend** (`themes.html`, white/navy): the RRG chart is the RRG page's **SVG renderer ported and re-themed** (navy quadrant tints/gridlines/tails), node labels are 5-char tags off the theme name; plus the ranking table + movers (reused from rankings.html), constituent tabs, and a theme editor (create/rename/delete + ticker textarea → the CRUD endpoints).
- **Routes:** `GET /themes.html`, `GET /api/themes?timeframe=&tail=` (ranking + rrg + leaders + theme defs, one payload), `POST /api/themes/{save,delete}`, `GET /api/themes/summary` (hub badge). Math/store/injection unit-tested in `tests/test_themes.py`.

## CANSLIM Module

William O'Neil / IBD's 7-factor growth-stock scorecard (C-A-N-S-L-I-M), served at `/canslim.html`. **The whole module is composition, not new quant** (the Themes precedent): each letter is read from a signal the harness already produces and blended into a 0-99 composite. Math + routes live in `modules/canslim/__init__.py`; the frontend is pure tables (no Plotly).

- **The 7 letters → existing signals** (each scored 0-100, `score_stock`): **C** quarterly EPS growth ← screener `fundamentals.eps_growth_q` (`_growth_score` vs the +25% `GROWTH_TARGET` bar, 75 at target asymptoting to 100); **A** annual growth ← `fundamentals.eps_growth_a`; **N** new high ← screener snapshot `pct_from_52w_high` (`_near_high_score`, full within 5% of the high → 0 by 30% below); **S** supply/demand ← the confluence **`ad_rating`** (demand: A→100…E→0) blended 0.75/0.25 with a small-float bonus (`shares_outstanding` cross-sectional percentile, smaller = scarcer); **L** leader ← a **cross-sectional RS rating** = `rankings._percentile_mapper` over the universe's snapshot RS blend (`rs_1m`/`rs_3m`) — IBD's RS-Rating idea, where cross-sectional (vs rankings' pooled-historical sector use) is the *correct* read for "percentile vs all stocks"; **I** institutional ← the confluence **`institutional`** leaf over the screener's `inst_ownership_history` (% held + holder-count QoQ trend; **forward-accumulating** — `None`/dropped from the blend until two dated reads exist); **M** market direction ← breadth regime (`signal.current_regime()`), used as a per-stock **multiplier** (`MARKET_FACTOR`: HEALTHY 1.0 / NEUTRAL 0.85 / DETERIORATING 0.6 — don't fight the tape) **and** a banner, not a column.
- **Composite** (`_composite`): a `LETTER_WEIGHTS`-weighted average (`C .20/A .15/N .15/S .15/L .25/I .10`) **renormalized over the *available* letters** × the market factor → 0-99. **Fail-soft everywhere** — a missing letter drops out of the blend (so the page works before fundamentals finish syncing); a per-letter `pass` flag fires at ≥`PASS_SCORE`(60).
- **Reuses, never duplicates:** reads `screener.store.get_snapshot()` joined with `get_fundamentals()` (the `eps_growth_q/a` + `shares_outstanding` columns added in Phase 2a; populated by the screener's yfinance `.info` phases — Phase 4 sector lookup grabs growth for free, Phase 5 refreshes growth every `GROWTH_MAX_AGE`=30d, Phase 6 reads institutional ownership every `INST_MAX_AGE`=80d into `inst_ownership_history`), `breadth.store.get_members(universe)` for membership, `rankings._percentile_mapper`, the confluence `institutional` leaf (for I), and `signal.current_regime()`. No new downloads, no new store.
- **Caveats surfaced in the UI:** latest-known fundamentals (not point-in-time), today's universe membership (survivorship), needs a built screener snapshot + fundamentals, and **I is forward-accumulating** (scores only once two dated ownership reads exist) — same freshness honesty as the screener backtester.
- **Routes:** `GET /canslim.html`, `GET /api/canslim?universe=&limit=` (market block + scored leaderboard + note), `GET /api/canslim/summary` (hub badge: top name + composite). Scorers/composite/end-to-end unit-tested in `tests/test_canslim.py`. Reachable from every page's cross-nav + a hub card.

## News & Macro Events Module

A news & macro-events tracker served at `/news.html` — a **phased** module, **Phases 1–2 built**. It answers "what market-moving events are coming, is event risk imminent, and what's the latest headline flow?" Math/assembly + routes live in `modules/news/`; the frontend is pure tables (no Plotly). Built **free-first, fail-soft** — works with **zero new API keys**; free keys (`FRED_API_KEY`, `FINNHUB_API_KEY`, `ALPHAVANTAGE_API_KEY`) progressively enrich it.

- **Three data shapes, one module** (mirrors the design discussion): **calendar/events** (scheduled, forward-looking — two **week-by-week tracks**: Economic Calendar + Earnings), **news/feed** (unscheduled, backward — the Phase-2 headline feed), **macro pricing** (the **Rates & Curve** tab). **All four tabs are live** (Economic Calendar, Earnings, News feed, Rates & Curve).
- **Source adapters (`sources.py`, the `breadth/datasource.py` pattern — stdlib-only `urllib`+`xml.etree`, every source fail-soft to `[]`):**
  - **`FOMCSource`** — the 8-meeting/yr Fed schedule from a **static decision-date table** (2025–26, SEP/dot-plot meetings flagged), plus a `fed_news` "minutes released" event ~21 days after each meeting. Static for reliability; **verify/refresh annually** from federalreserve.gov. No key.
  - **`EconCalendarSource`** — if `FRED_API_KEY` is set, the **exact** FRED `releases/dates` calendar filtered to market-movers (CPI/NFP/GDP/PCE/PPI/retail…); else an **approximate monthly generator** (`_approx`) from predictable cadences (NFP = first Friday is exact; CPI/PPI/retail/PCE/GDP are nominal), each labelled "approximate — set FRED_API_KEY". No key required.
  - **FRED observations → econ Actual / Previous** (`ECON_SERIES`/`match_series`/`fred_observations`/`econ_actual_previous`, **keyed only**): a curated report-title→`(FRED series, units transform, display unit)` map (CPI→CPIAUCSL `pch`, payrolls→PAYEMS `chg`, GDP→A191RL1Q225SBEA `lin`, …) lets the FRED API do the MoM-%/level-change transform; a release in month M reports M-1, so **Actual is blank until that period is published** (upcoming rows show only Previous) and both come from FRED's **latest revised** values. Weekly series (jobless claims) are deliberately excluded so a number is never period-misaligned. Cached per (series, units) for the TTL; fail-soft → blank. **Median Forecast (consensus) has no free source** — it stays em-dash.
  - **`FedRSSSource`** — Fed press-release + speeches RSS (recent/backward `fed_news`/`fed_speech` items). No key.
  - **`EarningsCalendarSource`** — the **keyed-or-free-fallback** pattern (mirrors `EconCalendarSource`): if `FINNHUB_API_KEY` is set, the **broad** Finnhub `calendar/earnings` (symbol + date + `hour` BMO/AMC + **EPS estimate/actual**), **relevance-filtered** to focus list ∪ S&P 500 members (both lazy/fail-soft, with a `CAP` flood-guard if neither is available); else falls back to the **focus-list** `screener.store.get_fundamentals().earnings_date` (date + symbol only, no EPS). EPS/when/period ride in the event's `extra` JSON.
- **Importance (`classify_importance`)** — keyword → `high`/`med`/`low`; the calendar drops `low` to stay to the market-movers. Drives the All / High-impact filter and the event-risk gate.
- **Assembly (`calendar.py`)** — `refresh()` fetches every source and **upserts into the store** (TTL-cached `ensure_fresh`, 30 min, single-flight; no daemon — first request after the TTL refreshes inline, the rankings-holdings pattern; `POST /api/news/refresh` forces it). **`build_week_calendar(track, weeks)`** is the page's primary read — a MarketWatch-style **week-by-week** grid: Monday→Friday rows from the current week's Monday, each weekday carrying its events (empty days render "None scheduled"), `track="econ"` = `econ`+`fomc` kinds, `track="earnings"` = `earnings`. Columns: econ = **Time(ET) · Report · Period · Actual · Median Forecast · Previous** (Actual/Forecast/Previous are em-dash — consensus/actuals are a paid feed, shown for layout; `_econ_period` heuristically fills Period = prior month, prior quarter for GDP — exact for the curated lag-1-month set); earnings = **Time(ET) · Symbol · Period · EPS Est. · EPS Actual** (from `extra`). Econ Actual/Previous fill from FRED when keyed (above), Median Forecast always em-dash. `_fmt_time` renders `08:30`→`8:30 am`. The flat `build_calendar()` (upcoming/recent) remains for the CLI + is unrelated to the page.
- **Phase-2 news feed (`build_news_feed`, `kind="news"`, the "News feed" tab — DONE):** a reverse-chronological, day-grouped headline feed (**Time · Source · Headline · Tickers · Sentiment**) over four fail-soft sources: **`MarketNewsRSSSource`** (CNBC/MarketWatch/Yahoo RSS, no key), **`Edgar8KSource`** (SEC 8-K material events for the focus list — ticker→CIK via SEC `company_tickers.json` cached, one latest 8-K/symbol, SEC-appropriate UA, no key), **`AlphaVantageNewsSource`** (keyed `ALPHAVANTAGE_API_KEY` — NEWS_SENTIMENT → overall sentiment label + ticker tagging, ~25 req/day free), and **`PolygonNewsSource`** (keyed `POLYGON_IO_KEY` — Polygon/Massive `/v2/reference/news` → Benzinga ticker news + per-ticker insight **sentiment** normalized to Bullish/Bearish/Neutral + ticker tagging; the free tier covers news with a generous limit — its options tape/chains for the flow module are PAID-only, so translated wire reposts are deduped on `(published_utc, publisher, ticker-set)`). All four persist into the same `events` store (`source_name`/`sentiment`/`tickers` in `extra`); the feed sorts reverse-chron and a **Focus-only** toggle keeps items tagged with a focus-list ticker (positions ∪ watchlists). Marketaux news + a screener-alert-on-8-K wire are the obvious next adapters (drop-in).
- **Macro tab = Rates & Curve (`build_rates`, FRED-keyed — NOT fed-funds probabilities, by deliberate scope call):** the macro-pricing tab ships the **high-value, low-cost** regime read instead of the fragile FedWatch compute — Treasury yields + fed funds + curve spreads from FRED `series/observations` (reuses `fred_observations(series, "lin", limit=45)`). Per-rate latest + 1D/1W/1M **Δ in basis points** (`RATE_SERIES`: DFF/DGS3MO/DGS2/DGS5/DGS10/DGS30/DFII10 + the T10Y2Y/T10Y3M spreads), a **yield-curve** mini-SVG (3M→30Y, no Plotly), and an **inversion read** (10Y–2Y / 10Y–3M negative = inverted, a late-cycle/recession-risk flag — directly relevant since sector rotation is a rates story). **FRED-only** (no clean keyless source for the 2Y/fed-funds/spreads) → an "add FRED_API_KEY" CTA state without a key. **Fed-funds-rate *probabilities* were deliberately deferred** (context not alpha — already priced in; the data is the hardest to source free; breadth regime + the rotation gate + bond-sector RS already approximate the signal); if ever built, the highest-leverage slice is just the next FOMC's hold-vs-move odds feeding the event-risk banner, not a full probability grid.
- **The signal hook — `event_risk(horizon=10, alert_days=2)`** — the soonest `high`-impact `fomc`/`econ` event within the horizon; `flag` trips when it's ≤ `alert_days` out ("event risk: size smaller, tighten stops into the print"). This is what gets **wired into the rest of the harness** — but **frontend-pull, not a backend cross-import** (breadth/schwab must not import a module above them in `breadth → schwab → rrg`): **schwab.html** and **breadth.html** overlay an amber event-risk banner by fetching `/api/news/event-risk` (fail-soft, page never blocks), and the **hub card** badge reads `/api/news/summary`. The screener's existing `earnings_soon` alert is the canonical event-driven hook already; news becomes the calendar feeding it later.
- **Store (`store.py`, `modules/news/data/news.db`, gitignored):** WAL, per-call connections; `events` table with `UNIQUE(source, kind, event_date, title)` + `ON CONFLICT … DO UPDATE` so re-fetches dedupe (forward entries refresh, backward Fed items accumulate). Carries an **`extra` TEXT (JSON)** column (earnings `when`/`eps_est`/`eps_actual`/`period`) added via an ALTER-ADD migration in `init_db`. `settings` for future use.
- **Dependency position:** a **low consumer** — imports nothing at module load except `modules.Response`; reaches **up** only via **lazy, in-function, fail-soft** imports (`EarningsCalendarSource`/`Edgar8KSource`/`build_news_feed` → `screener.store`/`screener.poller.focus_list` + `breadth.store.get_members('sp500')` for the earnings relevance filter — all degrade to no-earnings/no-filter/no-focus, never an error). The cross-page wiring is one-directional **frontend** fetches, so no new backend edge.
- **Caveats surfaced in the UI:** econ dates are **approximate without `FRED_API_KEY`** (NFP excepted); econ **Actual/Previous fill from FRED only when keyed** (revised values) and **Median Forecast is always blank** (no free consensus feed); FOMC table is static (verify annually); earnings need **`FINNHUB_API_KEY`** for broad coverage + EPS (else focus-list); news feed sentiment/tagging needs **`ALPHAVANTAGE_API_KEY`** (else RSS + 8-K only).
- **Routes:** `GET /news.html`, `GET /api/news/calendar?track=econ|earnings&weeks=N&importance=high` (week grid), `GET /api/news/feed?focus=&limit=&days=` (Phase-2 headline feed), `GET /api/news/rates` (Rates & Curve), `GET /api/news/event-risk`, `GET /api/news/summary` (hub badge), `POST /api/news/refresh`. CLI: `python3 -m modules.news.cli [--days N] [--high] [--json]` (flat upcoming list). Sources/helpers/store/hooks/week-grid/feed/rates unit-tested in `tests/test_news_calendar.py` (no network — fake source against a temp DB).
- **Remaining / deferred:** **fed-funds-rate probabilities** (deliberately deferred — see the Rates & Curve bullet); **deeper Phase-2 wiring** (tag company news to positions on schwab.html + fire a focus-list screener alert on a new 8-K via the existing `notify` routing); **social (Reddit/StockTwits)** (X is no longer free/reliable — the Polygon-stub deferral pattern).

## Confluence Layer (`modules/confluence/`)

A **routeless shared factor library** — pure leaves (numpy/pandas only, no I/O, no upward imports) at the BOTTOM of the dependency order. Each factor reads a symbol's own price (and where relevant volume) and emits a **signed contribution** other modules fold into a decision: the RRG `_conviction` engine sums them into the rotation-call score; the flow scoring engine reads them as Rule-6 context. This generalizes the original `flags`/`exhaustion` leaf pattern into one organized, extensible home.

- **Factor contract:** a leaf exposes a pure `current(...)` head-bar read + `contribution(read) → (signed_amount, label)` (the consumer scales by a theory-fixed weight) + optional vectorized `panels(...)`. `__init__.py` keeps a `FACTORS` registry so consumers can discover/iterate. **Adding a factor = drop a `<name>.py` + register it.** The fetch/orchestration that feeds a leaf prices stays in the *consumer* (e.g. `signal.exhaustion_for`/`volume_profile_for` use `fetch_ohlc`) so the leaf has no I/O and no cycle.
- **`flags.py`** / **`exhaustion.py`** — MOVED here from `rrg/` (single source of truth, shared with the screener's vectorized panels + the flag backtest). Behavior unchanged; only the import path moved (`modules.confluence.flags`/`exhaustion`).
- **`volume_profile.py`** — NEW leaf. Volume-at-price over a trailing window (each bar's volume spread across its high–low into bins — the standard bar-based approximation; no tick tape needed). Derives **POC** (point of control), **VAH/VAL** (70% value area = a fair-value band: below VAL = discount, above VAH = premium), **HVN/LVN** nodes, and a **profile shape** classifier → `D` (balanced) / `P` (fat top) / `b` (fat bottom) / `B` (double distribution) / `trend` (flat). `current()` returns shape + levels + the price's zone; `contribution()` is graded in [−1,1] (discount + bottoming `b` = bullish; premium + topping `P` = bearish). Wired into RRG conviction as a **live-only** factor (`W_VOL_PROFILE=12`), exposed to the flow tool's Rule-6 confluence. Unit-tested in `tests/test_confluence_volume_profile.py`.
- **`accumulation.py`** — NEW leaf, the **institutional buy/sell footprint** (CANSLIM's *demand* side of **S** and the price-volume read of **I**) — the standing accumulation/distribution read that `volume_profile` (price *location*) and `exhaustion` (one-bar *climax*) don't measure. Three tells over a trailing `WINDOW=50` bars, blended: **U/D Volume Ratio** (Σ up-close-day volume ÷ Σ down-close-day volume — IBD's metric; >1 accumulation), **Chaikin A/D line** direction vs price → a **divergence** read (`distribution` = price up while A/D falls — selling into strength; `accumulation` = the mirror), and **accumulation/distribution days** (close in the top/bottom half of range on ≥1.25× avg volume). `current()` returns `{ud_ratio, rating, adl_dir, divergence, accum_days, distrib_days}`; `contribution()` is graded in [−1,1] → an **A–E rating** (A strong accumulation … E heavy distribution). Wired into RRG conviction as a **live-only**, trailing/no-lookahead factor (`W_ACCUM=13`, so promotable into the backtest later like volume_profile); vectorized `panels()` → the screener `ad_rating` field (+ the "Under Accumulation" seeded screen); exposed to the flow Rule-6 confluence (`accumulation` chip + ±0.30 soft boost). Unit-tested in `tests/test_confluence_accumulation.py`.
- **`institutional.py`** — NEW leaf, CANSLIM's **I** (institutional sponsorship). **Unlike the other leaves it reads OWNERSHIP numbers, not OHLCV** (institutional %-held + holder count, which the consumer fetches via yfinance), so the leaf takes those numbers as inputs and stays pure. The signal is mostly the **quarter-over-quarter change** (funds adding = bullish, distributing = bearish) with a small level band (lacking sponsorship `<15%` or crowded `>92%` = mild negative; healthy band = mild positive). `current(pct_held, pct_held_prev, holders, holders_prev)` → read; `contribution()` → signed `[-1,1]`; `score()` → the 0-100 CANSLIM letter. **Consumed by CANSLIM only — NOT wired into RRG sector conviction** (ownership is meaningless for ETFs). Registered in `FACTORS` for discoverability. Caveat (forward-accumulating): the QoQ delta emerges only once the store holds two dated reads; before then it's a level-only read. Unit-tested in `tests/test_confluence_institutional.py`.
- **`wave.py`** — the cohesive **wave engine** (significant-swing ZigZag → wave labels, golden-pocket vs shallow retrace depth, wave-3/5 Fib extensions, the ABC corrective family, dual RSI divergence) on a security's raw RS line, **extracted verbatim from `rrg.signal`**. Unlike the single-factor leaves above, its pieces share **one no-lookahead ZigZag pass** in `_wave_features`, so they travel together (it is NOT in the `FACTORS` registry). `rrg.signal` stays the consumer: it keeps the price-fetch orchestration, the multi-timeframe blend (`_attach_mtf`/`_mtf_features`, which call `wave._wave_features`), the `_conviction` combiner, and `_rotation_call` (the RRG decision policy) — importing the engine as `wave_eng` (aliased to avoid the local `wave` = wave-label shadow in `_conviction`). The one searchable wave param `ZIGZAG_K` is single-sourced in `wave._WAVE_DEFAULTS` and merged into `signal.DEFAULTS`. **The extraction is guarded by a golden-master test** (`tests/test_rrg_golden.py`): it pins the full `compute_rrg` output (both intervals, incl. the MTF blend) on a deterministic synthetic panel to a committed fixture and asserts byte-identical — a pure move must not change a value. Regenerate the fixture only when behavior is *meant* to change.

## Options Flow Module

Unusual options activity — alert when whales enter/exit large positions, encoding a successful flow trader's 6-rule filter (~90% of flow is noise: hedges, spreads, rolls, exits). Built on **Schwab option-chain SNAPSHOTS** via a pluggable `source` adapter; a future Polygon trade tape upgrades the two tape-only signals with **zero scoring change**.

- **The 6 rules → named-constant gates in `scoring.py`** (pure, unit-tested in `tests/test_flow_scoring.py`): (1) **A/AA aggressive buy** — Schwab can't see the tape, so the aggressor is ESTIMATED from `last` vs bid/ask and is **advisory only, never a gate** (a Polygon source reports confirmed `_A`/`_AA` → it becomes a gate; `aggressor_method` flips `estimated`→`confirmed`); (2) **size in context** — premium notional ≥ a floor AND ≥ a multiple of the ticker's *own* avg daily options notional AND large vs OI; (3) **VOL vs OI** — VOL<OI = churn (dropped), ≥5× interesting, ≥20× fresh money; the next-morning **OI delta** resolves entered vs exited; (4) **form** — repeated prints (**clusters**) from snapshot diffs (sweeps/blocks are Polygon-only); (5) **timeframe** — favor swings, deprioritize 0DTE/insane-OTM lottos; (6) **confluence** — sector RRG call + breadth regime + golden pocket + volume-profile value area (annotate + **soft boost**, never hard-suppress). `classify_contract` returns `conviction` (0–100) + a `classification` bucket (`noise`/`watch`/`notable`/`conviction`) + a signed `direction` + a factor breakdown; hard-gate failures short-circuit to `noise` with the reason.
- **Pluggable source (`source.py`, mirrors `breadth/datasource.py`):** `OptionsFlowSource` interface (`get_chain` + `get_trades` + `supports_aggressor`/`supports_trade_tape` capability flags). `SchwabOptionsSource` parses `GET /marketdata/v1/chains` (strikeCount-bounded, `includeUnderlyingQuote`) into normalized contracts (reuses `breadth.datasource.RateLimiter` + `schwab.get_access_token`). `PolygonOptionsSource` is an inert pluggable stub (reads `POLYGON_API_KEY`, `get_trades` raises NotImplemented). `resolve_source(preferred)` factory, fail-soft.
- **Poller (`poller.py`, clones `screener/poller.py`):** singleton daemon, market-hours gate, ~90s tick. Each pass: `merge_universe(focus_list())` (curated liquid-options seed ∪ Schwab positions ∪ watchlists) → per underlying `get_chain` → `store.record_poll` diffs vs the prior snapshot for volume deltas + clusters → `scoring.classify_contract` (with `context.build_context` Rule-6 confluence, batched/fail-soft) → persist non-noise `flow_signal`s + dispatch `notable`+ alerts (`notify` reuses the screener's Discord/SMTP senders, `flow_channels` routing). The first pass of a new day runs `confirm_entries` — the **next-morning OI-confirmation** pass that resolves prior-day signals into `opened`/`closed`/`flat` from the OI delta.
- **Store (`store.py`, `modules/flow/data/flow.db`, gitignored):** WAL, per-call connections; `contract_state` (diff/cluster), `flow_signal` (feed), `oi_history` (T+1 confirm), `ticker_baseline` (trailing avg daily options notional — Rule 2), `flow_alert` (`UNIQUE(date, option_symbol, rule_key)` + `INSERT OR IGNORE` dedupe), `settings`. Integration-tested in `tests/test_flow_store.py` (hermetic temp DB + fake source).
- **Honest caveats (surfaced in the UI banner):** Schwab = snapshots not the tape → A/AA estimated, no sweep/block, sub-tick prints missed; OI prints once daily → entered/exited is **T+1** (intraday VOL/OI is the proxy). The Polygon upgrade path closes all three with no scoring/engine change.
- **Routes:** `GET /flow.html`, `GET /api/flow/{feed,contract,summary,status}`, `POST /api/flow/{sync,settings,poller}`. Frontend `flow.html` (white/navy): feed table with a default-ON **"conviction only"** toggle (the 90%-noise cut), per-rule filters, an ESTIMATED-aggressor badge, confluence chips, entry/exit column, and per-contract factor drill-down.

## Harness Module (`modules/harness/`)

The AI subagent harness — **CLAUDE.md's Planned Expansion #3, the project end-goal**, served at `/harness.html`. It is the **absolute TOP consumer**: it turns every data module's signal into a signed **VOTE**, combines them deterministically, arbitrates by regime, and has Claude **narrate** the result into one daily brief. The guiding finding (Notes.txt / the `subagent-harness-plan` memory): **no single module has standalone forward alpha in a concentration regime**, so the edge is **confluence + regime arbitration** ("concentrate when breadth is narrow, rotate when broad" — detect-and-adapt, not "beat the regime").

- **Two layers, deliberately separated.** (1) **The combiner is the decision** — `combiner.py` is **deterministic and LLM-free** (a cross-agent `signal._conviction`), so it is replayable/backtestable by the existing `rrg/backtest.py` referee and runs at **$0/offline**. (2) **The LLM only explains it** — `agents.py` narrates the combiner's number/stance and surfaces cross-domain agreement/conflict; it is **anchored** (never overrides the math). This split is what protects the validated finding (only deterministic decisions can be scored by the referee).
- **The vote (`votes.py`, Notes.txt step 3):** `{ domain, scope, direction (+1/0/-1), conviction (0-100), weight, factors[[label,amt]], horizon, regime_context, rationale, ok, detail }`. One **fail-soft** `vote_<domain>()` per module, each a **lazy, in-function import** reusing the module's existing entrypoint (no new quant): **breadth** (`build_summary` → the regime **arbiter**, top weight, HEALTHY +1/DETERIORATING −1), **rrg** (`compute_rrg` → net bullish-vs-bearish call conviction; per-sector calls + rotation gate in `detail`), **rankings** (offensive-vs-defensive sector leadership tilt), **canslim** (growth-leader strength), **flow** (`store` lead whale direction — note flow stores direction as the string `bullish`/`bearish`, normalized via `_dir_sign`), **news** (`calendar.event_risk` → a **risk-gate damper** + curve inversion), **screener** (`store.alerts_summary` → bullish-vs-bearish alert keys), **themes** (top theme rank). Weights are theory-fixed in `WEIGHTS` (breadth 30 … themes 6). A module with no data abstains (`ok=False`) and is skipped — the harness degrades gracefully as the breadth backfill / screener snapshot come online.
- **The combiner (`combiner.py`):** sums `direction × conviction/100 × weight × stance_factor` (the signed `add(amt,label)` pattern of `_conviction`), clamps to ±100, → `{score, posture, stance, factors, longs, avoids}`. **Regime arbitration is applied last** (mirrors the rotation gate in `_conviction`): `decide_stance(regime, rotation)` → **ROTATE** (HEALTHY + rotation on) / **CONCENTRATE** (deteriorating OR rotation off) / NEUTRAL; in CONCENTRATE the RRG *rotation* bet is halved (`_stance_factor`, the validated finding) and leadership votes (rankings/canslim) are leaned into. **`_sector_confluence`** is the cross-domain read on the **sector ETFs** (the one scope RRG and rankings share directly — no fragile stock→sector map): a sector RRG calls bullish **AND** rankings ranks highly gets a ×1.25 **agreement bonus** so confluence outranks a lone signal → `longs`/`avoids`. (The two RRG extension warnings count to the **bullish** side — continuation per the event study, not exits.)
- **The LLM layer (`agents.py`) runs on the user's Claude SUBSCRIPTION, not the metered API** (no `ANTHROPIC_API_KEY`, no per-token cost, no new dependency): `claude_cli()` shells out to the local `claude` binary headlessly — `claude -p --output-format json --model <m> [--append-system-prompt …]` with the prompt on **stdin** — and parses `result`. Fail-soft → `None` on missing-binary/timeout/error, so `master_brief` (Opus 4.8) and `domain_rationale` (Haiku 4.5) fall back to a **deterministic template**. Model aliases (`opus`/`haiku`) are env-overridable (`HARNESS_MASTER_MODEL`/`HARNESS_DOMAIN_MODEL`); `HARNESS_LLM=0` forces the free path. **Cost posture:** default ONE master synthesis call per refresh (per-domain rationales default to free templates; `HARNESS_DOMAIN_LLM=1` narrates each with Haiku). On-demand + cache: a memory TTL (30 min) + a `data/brief_<date>.json` file, so a page load generates at most once/day and `/api/harness/summary` (hub badge) reads the cache only — never an LLM call or full recompute.
- **The Referee (Phase 2, `modules/harness/backtest.py`) — Notes.txt step 5, built.** Validates the COMBINED decision: it has the harness emit its own point-in-time `{call, conviction}` panel (`build_harness_calls` → `combiner.score_sectors` per date, with the date's regime STANCE so CONCENTRATE halves the RRG rotation bet) in the **same shape as `signal.replay_calls`**, then runs BOTH that panel and the raw-RRG panel through the *exact* `rrg/backtest.py` machinery (`_event_records`/`_event_study`/`_regime_split_study` + `_rotation_portfolio` + `_equity_curve`) for an **A/B: harness confluence vs raw RRG vs SPY/RSP-matched**. `score_sectors` is the single source of truth shared with the live brief's `_sector_confluence` (live path passes `stance=None`, behavior unchanged). **Point-in-time SUBSET only** (the honest scope): breadth regime (`regime_series`+`align_labels`), RRG calls, rankings (cross-sectional RS via `_rank_panel`, no-lookahead), and the rotation gate — flow/news/screener/canslim stay live-only refinements, excluded; the LLM plays no part (only the deterministic combiner is scored). **Honest finding (11-ETF/3y, a concentration regime — direction not proof):** the harness does NOT beat beta on absolute return (the regime is mostly beta), **but regime-arbitrated confluence sharpens the RELATIVE signal vs raw RRG** — the long-hedged (long−benchmark) book and the ROTATE-IN forward excess are both better/less-negative than RRG's (vs RSP: hedged ≈ +4% vs +3%, IN-excess ≈ +0.0% vs −0.3%). That's signal-QUALITY, not absolute alpha; the **Phase-3 gate** is whether that relative edge survives costs + the live-only votes, not headline return. Numbers drift run-to-run with live yfinance (the "direction, not precision" caveat). Unit-tested in `tests/test_harness_backtest.py` (score_sectors / call-panel / A/B verdict / a synthetic-panel end-to-end with `_load` mocked — no network).
- **Routes:** `GET /harness.html`, `GET /api/harness` (full brief payload, cached), `GET /api/harness/summary` (hub badge — stance + score + top long, cache-only), `POST /api/harness/run` (force regenerate, re-runs the LLM), `POST /api/harness/backtest` (the referee A/B → JSON). CLI: `python3 -m modules.harness.cli [--llm] [--json] [--backtest]` (no-LLM default). Frontend: the brief page + a compact **"Referee"** A/B panel (run-on-demand button, no Plotly). Unit-tested in `tests/test_harness.py` + `tests/test_harness_backtest.py` (no network; the `claude` subprocess + `_load` are mocked).
- **Open follow-ups:** Phase 3 paper-trading automation (gated on the referee showing the relative edge survives costs + the live-only votes); a richer referee surface (Plotly equity overlay / benchmark + universe dropdowns — the route already accepts them); a chat UI / multi-turn agent debate (the "collaborative discourse" beyond the master synthesis).

## Development Conventions

- One `modules/<name>/` folder per data domain. No cross-module imports except: schwab imports `compute_rrg`, `BENCHMARK`, `DEFAULT_TICKERS` from rrg (intentional — schwab signals are derived from RRG); breadth imports `get_access_token` from schwab (intentional — schwab owns OAuth, breadth reuses the authenticated session for market data); screener imports breadth's `store`/`universes`/`datasource` (bars + RateLimiter — breadth owns price history), schwab's `get_access_token`/`get_position_symbols`/`SECTOR_ETF_MAP`/`_read_env`, and rrg's `compute_rrg` for sector context (all intentional — screener is a consumer of every other module's domain); rankings imports rrg's `signal` (RS math + cached price fetch, `DEFAULT_TICKERS`/`SECTOR_NAMES`/`BENCHMARK`) and screener's `store` (`fetch_sector_leaders` + `get_flag_winrates`/`fetch_signal_states` + `snapshot.start_refresh` for the flagstats kick — intentional, rankings is a consumer of both); themes imports rrg's `signal`/`compute_rrg` and rankings' `compute_rankings`/`_ret`/`_rel`/`flag_stats_for` (it feeds synthetic theme-index panels through both engines via the `close=` param — intentional, themes is a top consumer); canslim imports rrg's `signal` (`current_regime`), rankings' `_percentile_mapper`, and screener's `store` (`get_snapshot`/`get_fundamentals`/`get_members` via breadth) — pure composition, a consumer of every other module's signal (no new quant); `confluence/` is a **routeless pure-leaf library at the BOTTOM of the dependency order** (numpy/pandas only) that `rrg.signal`, `screener.metrics`/`snapshot`, and `flow.scoring` all import down into — its `flags`/`exhaustion` leaves were moved out of `rrg/` (so `screener.metrics`/`snapshot`, `rrg.signal`/`flag_backtest` now import `modules.confluence.flags`/`exhaustion`, NOT `modules.rrg.*`); the fetch/orchestration that feeds a leaf prices stays in the *consumer* (`signal.exhaustion_for`/`volume_profile_for`/`accumulation_for`) so the leaf takes no upward import. `flow` is the **top consumer**: it imports `schwab` (`get_access_token`/`get_position_symbols`/`SECTOR_ETF_MAP`/`_sector_etf`/`_read_env`), `breadth.datasource.RateLimiter`, `rrg.compute_rrg`/`signal`, `screener.store`/`notify` (transport reuse) — all intentional, all lazy/fail-soft where reaching across. `news` is a **low consumer with no module-load cross-imports** (only `modules.Response`): its `EarningsSource` reaches into `screener.store` via a **lazy, in-function, fail-soft** import, and the schwab/breadth event-risk overlay is a **frontend** fetch of `/api/news/event-risk` (not a backend import), so no module above news in `breadth → schwab → rrg` ever imports it. rrg's `signal`/`flag_backtest` and screener's `snapshot` reach UP to `breadth` (`_full_series` + `regime.regime_series`/`align_labels`) **only via lazy, in-function, fail-soft imports** — `breadth → schwab → rrg` means rrg must NOT import breadth at module load, so the regime is fetched at call time and degrades to basket-default weighting if breadth is unavailable. `harness` is the **ABSOLUTE TOP consumer** (the synthesis layer — nothing imports it back): its `votes.py` reaches into every data module via **lazy, in-function, fail-soft** imports (`breadth.build_summary`, `rrg.compute_rrg`/`signal`, `rankings.compute_rankings`, `canslim.compute_canslim`, `flow.store`, `news.calendar`, `screener.store`, `themes.compute_theme_view`) to build signed votes, and `combiner.py` (pure) folds them — so a missing/erroring module just abstains (`ok=False`). It reaches Claude through the local **`claude` CLI subprocess** (`agents.claude_cli`, subscription auth, no API key), never at module load and never on the homepage badge path.
- **Palette:** home, breadth, schwab, screener, rankings, themes, flow, canslim, news, and harness share a **white/navy** theme (`--bg #ffffff`, `--panel #f4f7fc`, `--ink #0e2148`, navy `--accent #16336e`, green `#1a9d6b`, red `#d1453b`, blue `#2f6fb3`); **RRG is intentionally left on the original dark theme.** Each page keeps the same `:root` variable *names*, so re-theming is mostly a value swap — but several things hold literal hex outside `:root` and must be updated by hand: Plotly layouts (`plot_bgcolor`/`gridcolor`/trace colors in breadth & screener), tint-backed badge/pill/flag/regime/kind classes (their dark *text* colors), and schwab's `--c-watch` (amber, kept distinct from the navy accent). Button text on the accent is `#fff`.
- Prefer free data sources first (yfinance, FRED, etc.) before paid APIs.
- No build pipeline — vanilla Python stdlib server, vanilla JS in HTML. Add a framework only when the UI complexity genuinely requires it.
- Business logic lives in module `__init__.py`. `app.py` stays thin.
